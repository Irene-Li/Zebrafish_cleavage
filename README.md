# Zebrafish cleavage — active-gel modelling

Code and data accompanying the paper on furrow formation during zebrafish
cleavage. The repository contains the continuum active-gel models (finite-element
solvers built on [NGSolve](https://ngsolve.org)), a JAX model of furrow
constriction energetics, the experimental measurements used for comparison, and
the notebooks that reproduce the figures.

---

## 1. Installation

The code was tested with **Python 3.11** on macOS (Apple Silicon) and Linux.
Install into a fresh virtual environment:

```bash
python3.11 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

This installs the finite-element stack (NGSolve/Netgen), JAX + Diffrax + Optax,
and the image/analysis libraries. Then launch Jupyter and open any notebook:

```bash
jupyter lab           # or: jupyter notebook
```

> **Run notebooks from the `notebooks/` directory.** Every notebook assumes its
> working directory is `notebooks/` (the Jupyter default when you open a file
> there). Committed data is read as `../data/...`; generated data is written
> under `sim_data/` — see [§4](#4-data-and-path-conventions).

## 2. Repository layout

```
Cleavage/
├── requirements.txt
├── src/                     # models and helpers (added to sys.path by the notebooks)
│   ├── active_gel_fem.py        # NematicActiveGel 1D/2D/Circle — base single-fluid model
│   ├── myosin_actin_gel_fem.py  # MyosinActinGel2D — coupled actin+myosin gel
│   ├── double_fluid_gel_fem.py  # DoubleActinGel2D — exploratory two-component gel (not used in the paper)
│   ├── catch_bond_fem.py        # CatchBond variants (model exploration; not used by a notebook)
│   ├── constriction.py          # JAX furrow-constriction energy model
│   └── utils.py                 # source fields, colourbars, 2D plotting/animation helpers
├── scripts/
│   └── chi0_chi1_scan.py    # χ0–χ1 grid scan (writes sim_data/acto_myo/, cluster-scale)
├── notebooks/               # one notebook per analysis / figure set (see §3)
├── data/                    # experimental measurements committed to the repo
│   ├── actin_data/              # kymographs, lifeact intensity/position line plots
│   ├── actin_kymo/              # per-replicate kymograph TIFFs + cable nematic-order .npz
│   └── furrow_position_h1_h2/   # furrow-position time traces (WT / Ca-free / caRhoA)
├── figures/                 # figure outputs (git-ignored except a few committed PDFs/PNGs)
└── sim_data/                # simulation outputs — git-ignored, regenerated (see §4/§5)
```

All of `data/` is committed, so every notebook that depends only on experimental
data runs straight from a fresh clone.

## 3. Notebooks

Notebooks marked **†** require NGSolve (installed via `requirements.txt`); the
rest use only the pure-Python stack.

### Run directly from a fresh clone

| Notebook | What it does |
|---|---|
| `data_analysis.ipynb` | Actin kymograph and lifeact intensity/position analysis. Reads committed `data/actin_data/`. |
| `constriction1.ipynb` | Furrow-constriction energetics compared against the measured furrow positions (WT / Ca-free / caRhoA). Reads committed `data/furrow_position_h1_h2/`. |
| `constriction2.ipynb` | Phase-2 constriction energy landscape and phase diagram. Self-generates `sim_data/constriction/` (a few minutes). |
| `furrow_width.ipynb` | Depletion-zone width vs. velocity and cable nematic order, from the kymograph TIFFs in committed `data/actin_kymo/`. (An optional simulation overlay from `sim_data/caRhoA.npz` is off by default.) |
| `active_gel_fem.ipynb` **†** | Base nematic active-gel model (1D/2D): isotropic vs. banded state. Source field defined inline — no external data. |
| `actin_myo_gel.ipynb` **†** | Coupled actin–myosin gel; 2D furrow kymograph. No external data. |
| `caRhoA_actin_dynamics.ipynb` **†** | caRhoA perturbation sweep → velocity / depletion-width / nematic-order scaling. Runs ~22 simulations (~4 min) and writes `sim_data/caRhoA.npz`. |

### Needs a regenerated scan first (see §5)

| Notebook | What it does |
|---|---|
| `chi0_chi1_scan_analysis.ipynb` | Summarises the χ0–χ1 contractility scan. Reads `sim_data/acto_myo/`, produced by `scripts/chi0_chi1_scan.py`. |

## 4. Data and path conventions

- **Committed experimental data** lives in `data/` and is read as `../data/...`.
- **Simulation outputs** are written under `sim_data/` and are **git-ignored** —
  they are regenerated by the code, not shipped. There are two locations, both
  intentional given the working-directory convention:

  | Output | Written by | Path (relative to repo root) |
  |---|---|---|
  | `sim_data/constriction/*.npy` | `constriction2.ipynb` | `notebooks/sim_data/constriction/` |
  | `sim_data/caRhoA.npz` | `caRhoA_actin_dynamics.ipynb` | `notebooks/sim_data/caRhoA.npz` |
  | `sim_data/furrow_width_data.npz` | `furrow_width.ipynb` | `notebooks/sim_data/` |
  | `sim_data/acto_myo/*.npz` | `scripts/chi0_chi1_scan.py` | `sim_data/acto_myo/` (repo root) |

  The scan **script** (`scripts/chi0_chi1_scan.py`) writes to the repo-root
  `sim_data/`, and `chi0_chi1_scan_analysis.ipynb` reads it as `../sim_data/acto_myo`.
  Everything launched from a notebook writes to `notebooks/sim_data/`. Notebooks
  create these directories automatically before writing.

## 5. Regenerating simulation data

Some simulation outputs are **not** stored in the repository. Their generating
code is included; regenerate before running the analysis. The χ0–χ1 scan is
compute-heavy (originally run on a cluster) — timings below are single-machine
estimates.

**χ0–χ1 contractility scan** (for `chi0_chi1_scan_analysis.ipynb`)

```bash
python scripts/chi0_chi1_scan.py
```

Runs a 50×50 grid of `MyosinActinGel2D` simulations → `sim_data/acto_myo/`
(~2500 files, on the order of 10+ GB and several hours). Edit `n_chi` near the
top of the script to run a coarser, faster grid. Then run
`chi0_chi1_scan_analysis.ipynb`.

**caRhoA summary** (for the optional overlay in `furrow_width.ipynb`)

Run `caRhoA_actin_dynamics.ipynb` end to end (~4 min); it writes
`sim_data/caRhoA.npz`. `furrow_width.ipynb` runs fine without this file — the
overlay it feeds is disabled by default.

---

## 6. Reproducibility notes

- A fresh venv built from `requirements.txt` runs every notebook documented here;
  each was executed top-to-bottom during preparation (the χ0–χ1 scan was validated
  both on a reduced grid and against the full dataset).
- Notebooks add `../src` to `sys.path` themselves, so no installation of the
  `src` package is required.
- Figure outputs land in `figures/` (git-ignored) and do not need to be committed
  to rerun anything.
